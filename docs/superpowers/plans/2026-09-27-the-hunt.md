# The Hunt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phase nine: a lifting coach and logger on AURA-1 and the dashboard, runs and recovery from Garmin, a daily verdict, and the energy ledger.

**Architecture:** Pure coach/verdict/ledger functions in `@aura/shared`; Hunt tables, routes and a sync extension in the Fastify API; a Python sidecar feeding Garmin data to an internal ingest route; a HUNT place in the firmware's session machine; the Hunt pane rebuilt on the store.

**Tech Stack:** TypeScript, zod 4, Fastify 5, Drizzle, Postgres 17, Vue 3, canvas plates, Python 3.12 + garminconnect >= 0.3.5, Arduino-ESP32 C++.

**Spec:** docs/superpowers/specs/2026-09-27-the-hunt-design.md

## Global Constraints

- No emojis anywhere. Monochrome, never pure #000000 on the web.
- Exercise names <= 15 characters (the glass).
- The Hunt stays out of Insight XP and decay; device lift sessions stay ordinary HUNT/lifting sessions.
- Garmin ingest is internal only (compose network), never under /sync.
- Sets and feels are idempotent by uuid / (exercise, date).
- Web verified by vue-tsc and build only.

## Review Focus

- A set synced twice (device retry) is stored once.
- An exercise with no history gets its seeded start load as the prescription.
- No Garmin data at all: verdict still answers from the log.
- Bodyweight exercises (muscle ups) never get a load step.
- Power loss mid-hunt: sets already done stay queued; the session recovers as today.
